# Vistara — Day 17: API Design

> Corrected — added the ML service API contract, previously missing entirely.

## 1. Conventions

Base path `/api/v1` for the main backend. ML service runs internally at a separate base path (not exposed to the frontend directly — backend proxies and validates all ML output).

## 2. Backend Endpoints (Unchanged from Original Day 17, Verification Section Corrected)

| Method | Endpoint | Maps to |
|---|---|---|
| POST | `/auth/register`, `/auth/login`, `/auth/logout` | FR-AUTH |
| POST/GET/PUT | `/properties`, `/properties/:id` | FR-PROP |
| GET | `/search`, POST `/search/ai` | FR-SEARCH |
| POST | `/bookings`, GET `/bookings/:id`, `/bookings/my` | FR-BOOK |
| POST | `/payments/create-order`, `/payments/webhook` | FR-PAY |
| POST | `/properties/:id/requirements` | FR-REQ |
| POST | `/bookings/:id/review` | FR-REVIEW |
| POST | `/bookings/:id/mismatch-report` | FR-MISMATCH |

**Verification (corrected):** no `/verification` submission endpoint from the host — verification is now triggered automatically when property images are uploaded (`POST /properties/:id/images` internally queues a photo-verification job via the ML service). `GET /properties/:id/verification-status` returns the current badge state. `PUT /admin/verification/:id/decide` remains for admin review of FLAGGED cases.

## 5. ML Service Endpoints (New — Corrected)

| Method | Endpoint | Serves |
|---|---|---|
| GET | `/ml/recommendations?userId=` | FR-REC-01/02 — ranked property list |
| POST | `/ml/risk-score` | FR-RISK-01 — body: booking/mismatch/verification signals; returns risk score + contributing factors |
| POST | `/ml/review-summary` | FR-REVIEW-04 — body: review texts for a property; returns aspect scores + summary |
| POST | `/ml/photo-verify` | FR-VERIFY-01/02 — body: image reference(s); returns duplicate/consistency result |

## 6. Backend-to-ML Integration Pattern

```
Backend receives request -> Backend calls ML service internally -> 
ML service returns prediction -> Backend validates output shape/range -> 
Backend persists result (TRUST_SCORE, REVIEW_SUMMARY, PROPERTY_IMAGE fields) -> 
Backend returns response to frontend
```

The frontend never calls the ML service directly — this keeps a single point of validation and auth enforcement, per NFR-SEC-02.

## 7. AI Search Failure Handling (Unchanged)

`/search/ai` still returns `AI_UNAVAILABLE` on LLM failure, falling back to manual filters — this was correct in the original document.

## 8. Day 17 Conclusion

The API contract now includes the ML service Vistara's own roadmap requires, and the verification endpoint correctly reflects automated photo-based checks rather than a host document-submission flow.
