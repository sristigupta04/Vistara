# 1. Competitor Research

Day 7 mein humne major accommodation/travel platforms ko reference kiya:

* KAYAK
* Booking.com
* Agoda
* Vrbo
* Airbnb — primary reference

### KAYAK

KAYAK ka strong area accommodation comparison/discovery hai. Users multiple accommodation options ko compare kar sakte hain, filters use kar sakte hain aur current experience mein AI/free-form search bhi available hai.

**Observation:**

> Search + comparison + AI discovery already exists.

Therefore:

**AI Search alone ≠ Vistara USP**

---

### Booking.com

Booking.com ka accommodation ecosystem very broad hai.

Important observations:

* Large accommodation inventory
* Search and filters
* Reviews and ratings
* Property categories
* Natural-language/free-form search experience
* Booking management

**Observation:**

> Basic discovery, filtering, reviews aur natural-language search already mature areas hain.

Therefore:

**“Vistara has search + AI search” alone is not differentiation.**

---

### Agoda

Agoda ka ecosystem accommodation ke saath travel-related services ko combine karta hai.

Observed areas:

* Hotels
* Homes/apartments
* Activities
* Transport/travel services
* Accommodation filters
* AI-assisted room-selection experience

**Observation:**

> AI-based decision assistance itself is becoming common.

Therefore Vistara ko AI ko **Trust + Decision Making** ke saath connect karna hoga.

---

### Vrbo

Vrbo ka strong focus:

* Entire homes
* Villas
* Apartments
* Vacation homes
* Cabins
* Cottages
* Family/group-oriented stays
* Property-type discovery

**Observation:**

> Property categories aur specialized accommodation discovery already important UX patterns hain.

Therefore:

**Property categories = useful Vistara feature, but not USP.**

# 5. 🛡️ Trust-First Marketplace

Vistara ka biggest product direction:

> **User ko sirf property dikhani nahi hai; user ko property ke baare mein informed decision lene mein help karni hai.**

Trust layer:

```text id="trust01"
HOST
  ↓
Identity Verification
  ↓
Business Verification
  ↓
Property Verification
  ↓
Document / Certificate Verification
  ↓
Risk Analysis
  ↓
Trust Signals
```

User ko structured information milegi.

Example:

```text id="trust02"
✓ Identity Verified
✓ Property Information Checked
✓ Business Information Checked
✓ Documents Checked
⚠ Additional Review Required
```

**Important:**
`Suspicious` ka matlab automatically fraud nahi hoga.

It means:

> **Further investigation/review may be required.**

# 6. 🔐 Multi-Level Verification

Vistara verification ko single badge tak limit nahi karega.

### Level 1 — Identity

### Level 2 — Business

### Level 3 — Property

### Level 4 — Document / Certificate

Relevant documents/certificates ki validation.

```text id="verifyall"
   +

   +
Reports
        ↓
   TRUST / RISK SIGNAL
```

# 7. 🏠 Host Requirements System

Ye Vistara ke important differentiating workflows mein se ek hoga.

Host property ke liye requirements define karega:

```text id="req01"
Maximum Guests
ID Requirement
Age-related Requirement
Pet Policy
Smoking Policy
Check-in Rules
Check-out Rules
Property Rules
Required Documents
```

Guest booking se pehle ye requirements dekhega.

### Flow

```text id="req02"

          ↓
Guest views requirements
          ↓
Guest confirms:
"I have read and agree"
          ↓
Booking
```

---

# 8. 📌 Requirement Snapshot

Ye important technical/product decision hai.

Booking ke time:

```text id="snap01"
Host Requirements
        ↓
Booking Requirement Snapshot
        ↓
Booking Record
```

Agar host future mein requirements change karta hai, to existing booking ka agreement change nahi hoga.

Example:

Booking ke waqt:

> Pets allowed.

Later host changes listing to:

> Pets not allowed.

Existing booking ke liye original requirement snapshot preserved rahega.

This provides:

**Accountability + transparency + dispute context.**

---

# 9. 🔄 Post-Stay Mismatch Reporting

Vistara ka trust system booking ke baad end nahi hoga.

Actual stay ke baad:

```text id="mismatch01"
What host/listing claimed
          ↓
What guest experienced
          ↓
MATCH / MISMATCH
```

Guest significant mismatch report kar sakta hai.

Examples:

* Amenity unavailable
* Property description mismatch
* Room/property mismatch
* Parking unavailable
* Host requirement mismatch
* Property condition issue
* Other significant issue

Evidence:

* Description
* Photos
* Relevant booking information

> **Price ko understandable aur transparent banana.**

```text id="money01"
Cleaning Fee             ₹500
Platform Fee             ₹250
Taxes                    ₹675
────────────────────────────
Estimated Total         ₹4,925
```

Then:

```text id="money02"

Extra Charges    ₹1,425
```

The focus is not simply finding the cheapest stay.

It is:

> **Understanding what the user is actually paying.**

# 19. Final USP

### Long Version

> **Vistara is a trust-aware accommodation marketplace that combines property discovery and booking with identity, business, property and document verification, transparent requirements, post-stay feedback loops, risk signals and AI-assisted decision-making.**

### Short Version

> **“Don't just find a stay. Know what you're booking.”**

### Product Philosophy

> **Discover → Evaluate → Verify → Trust → Book → Stay → Review → Improve Trust**
